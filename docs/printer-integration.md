# เชื่อมเครื่องพิมพ์ร้าน

## เปิดใช้งานบน Windows ที่ต่อ USB

1. ติดตั้งไดรเวอร์ให้เห็นชื่อ **4BARCODE 4B-2054B** และมี Node.js ใน PATH
2. เปิด `tools/printer/Start-Printer.cmd` ตัวช่วยทำงานเฉพาะ `127.0.0.1:18767`
3. เปิด Siatoy POS รุ่นที่มีการเชื่อมนี้ → พิมพ์บาร์โค้ด → **เครื่องร้าน · 3 ช่อง**
4. เพิ่มสินค้าลงคิว ระบุจำนวน แล้วกดพิมพ์ หน้าต่างตัวช่วยแสดงลำดับรหัสซ้ายไปขวา
5. ตรวจรายการและกด **พิมพ์ตามคิว** ในหน้าต่างนั้น ต้องอนุญาต popup จาก POS

โหมดนี้ใช้แบบที่ทดสอบแล้ว: ชื่อ Siatoy TCG, ชื่อสินค้า, บาร์โค้ดสูง 8 มม. และรหัส ไม่พิมพ์ราคา ชื่อยาวตัดท้ายด้วย … ค่าช่องแสดงบนดวงและขนาดดวงสำหรับ browser จะไม่ทับโปรไฟล์เครื่องร้าน โหมดม้วน/A4 แบบเดิมยังเลือกได้

ใช้ได้กับ POS บน `https://siatoy-pos.vercel.app` และ development ที่ `http://localhost:8000` / `http://127.0.0.1:8000` เครื่องที่เปิด POS ต้องเป็น Windows เครื่องเดียวกับตัวช่วย ไม่รองรับการส่งจากโทรศัพท์คนละเครื่อง ตัวช่วยไม่ติดตั้ง autorun และไม่เปลี่ยนค่าไดรเวอร์ทั้งระบบ

## โปรไฟล์หลัก

`tools/printer/printer-profile.json` คัดลอกจากค่าที่เจ้าของร้านอนุมัติ: 32 × 25 มม. 3 ช่อง, gap แนวนอน 2 มม., offset ขวา 0.6 มม., offset ลง 4.8 มม., barcode width 90%, 203 dpi, bar height 12 มม. เก็บ driver stock เดิมไว้ (ตรวจครั้งก่อนประมาณ 105.92 × 29.97 มม. รวมขอบตามวิธีของไดรเวอร์) ไม่บังคับ custom stock 102 × 25 มม.

เรียงคิวตามจำนวนจริง แถวสุดท้ายเว้นช่องที่ไม่มีสินค้า ไม่ทำสำเนาเพิ่มให้เต็มแถว จำกัด 500 ดวงต่อครั้ง ระบบส่งเป็น PrintDocument หนึ่งงานหลายหน้า รหัสตัวเลขจำนวนคู่ใช้ Code 128 C; ตัวอื่นใช้ B ตัวเลือกเติม 0 ใน POS ยังคงทำงานและแสดงค่าที่ส่งจริงในตัวช่วย

ตัวอักษรที่ไม่ใช่ ASCII และรหัสที่กว้างเกิน 30 มม. ถูกปฏิเสธก่อนพิมพ์ทั้งหมด ช่วงรหัสตัวเลขใหม่และการพิมพ์หลายแถวยังต้องทดลองสแกนกับม้วนจริงก่อนใช้ล็อตใหญ่ ตำแหน่งแนวนอนใช้ค่าที่ผ่านการตรวจรูปแล้ว ส่วนแบบใหม่ที่เพิ่มชื่อสินค้าและลดความสูงบาร์โค้ดยังต้องตรวจแผ่นจริง

## การเชื่อม

หน้า POS เปิด popup localhost พร้อมคิวใน URL fragment (ส่วนหลัง # ซึ่งไม่ถูกส่งไป HTTP server และล้างจาก URL เมื่อรับแล้ว) เพื่อรองรับ browser ที่เปิดหน้าต่างภายนอกโดยไม่มี opener พร้อมใช้ `postMessage` ที่ตรวจ origin/window สำหรับการแจ้งสถานะ ไม่เรียก HTTP localhost ผ่าน fetch จากเว็บ HTTPS ตัวช่วยรับเฉพาะ opener จาก origin ที่กำหนด และต้องกดพิมพ์บนหน้าตัวช่วย จากนั้น POST แบบ same-origin พร้อม session token ไป `/print` ไม่มี CORS wildcard

งานมี UUID และป้องกันส่ง UUID ซ้ำตลอดอายุโปรเซส รวมงานที่เกิด error ด้วย เพราะอาจออกบางส่วนแล้ว ไม่มี automatic retry; ตรวจคิว Windows และจำนวนฉลากก่อนสร้างงานใหม่ การตอบสำเร็จหมายถึงส่งเข้าคิว Windows ไม่ใช่การยืนยันกระดาษจริง

ไฟล์งานชั่วคราวถูกลบหลังส่ง คำสั่ง PowerShell ใช้ `-ExecutionPolicy Bypass` เฉพาะโปรเซสของ helper ไม่แก้นโยบายระบบ

## ตรวจโดยไม่พิมพ์จริง

```powershell
node tools/printer/test.mjs
powershell.exe -NoProfile -ExecutionPolicy Bypass -File tools/printer/print-labels.ps1 -ValidateOnly
```

โค้ดเว็บที่แก้ยังต้องเผยแพร่ขึ้น GitHub Pages จึงจะมีปุ่มใหม่นี้บนเว็บจริง ไม่ควรเปิด `/session` หรือ `/print` ให้เข้าถึงจาก LAN

ชื่อสินค้า: ปรับเป็น 2 บรรทัดในพื้นที่สูง 5.5 มม. ใช้ Tahoma 6.5 pt และลดได้ถึง 5.5 pt ตามความยาว หากยังไม่พอจะแสดง … บาร์โค้ดยังคงสูง 8 มม. ตำแหน่งใหม่: ชื่อเริ่ม y=5, บาร์โค้ด y=10.8, รหัส y=19.8 มม. บวก offset แนวตั้งเดิม 4.8 มม.
